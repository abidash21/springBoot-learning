A client (browser, mobile app, etc.) communicates with a server using the **HTTP** or **HTTPS** protocol.

# HTTP (HyperText Transfer Protocol)

HTTP is the standard protocol used for communication between a client and a server.

## HTTP Request Structure

An HTTP request consists of:

1. **Method**
2. **URL / Path**
3. **Headers**
4. **Body**

### Example

```http
POST /users HTTP/1.1
Host: example.com
Content-Type: application/json

{
  "name": "John",
  "age": 25
}
```

### Request Components

| Component      | Description                                    |
| -------------- | ---------------------------------------------- |
| **Method**     | Specifies the operation (GET, POST, PUT, etc.) |
| **URL / Path** | Endpoint to which the request is sent          |
| **Headers**    | Additional metadata about the request          |
| **Body**       | Actual data sent to the server (optional)      |

### Common Headers

```http
Content-Type: application/json
Authorization: Bearer <token>
Accept: application/json
```

> Headers provide additional metadata about the request.

---

## HTTP Response Structure

An HTTP response consists of:

1. **Status Code**
2. **Headers**
3. **Body**

### Example

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "message": "User created successfully"
}
```

### Response Components

| Component       | Description                                 |
| --------------- | ------------------------------------------- |
| **Status Code** | Indicates success or failure of the request |
| **Headers**     | Metadata about the response                 |
| **Body**        | Data returned by the server                 |

---

# Common HTTP Methods

| Method     | Purpose                                 |
| ---------- | --------------------------------------- |
| **GET**    | Retrieve data                           |
| **POST**   | Create new data                         |
| **PUT**    | Replace an existing resource completely |
| **PATCH**  | Update part of an existing resource     |
| **DELETE** | Remove a resource                       |

# HTTP vs HTTPS

## HTTP

* Stands for **HyperText Transfer Protocol**
* Data is transferred in **plain text**
* Less secure
* Suitable only for non-sensitive communication

## HTTPS

* Stands for **HyperText Transfer Protocol Secure**
* **S = Secure**
* Uses **SSL/TLS encryption**
* Request and response are encrypted
* Protects data from attackers during transmission

```text
HTTP
Client -------------> Server
(Data is readable)

HTTPS
Client ====Encrypted====> Server
(Data cannot be read by attackers)
```

# How an HTTP Request Works in a Plain Java Application

Without using Servlets or Spring, a Java application must handle everything manually.

Steps involved:

1. Open a server socket
2. Read the incoming input stream using **BufferedReader**
3. Parse the HTTP request manually
4. Identify the endpoint
5. Map the endpoint to the corresponding method
6. Execute business logic
7. Build the HTTP response manually
8. Write the response back to the client
9. Handle multiple clients using multithreading

```text
Client
   │
   ▼
Read Input Stream
   │
   ▼
Parse HTTP Request
   │
   ▼
Find Endpoint
   │
   ▼
Call Method
   │
   ▼
Create HTTP Response
   │
   ▼
Send Response
```

### Challenges

* Manual request parsing
* Manual response creation
* Thread management
* Endpoint mapping
* Boilerplate code
* Difficult to maintain as the application grows

# Servlet

A **Servlet** is a Java class that handles HTTP requests and responses.

Instead of manually implementing networking logic, we write Servlets and let the **Servlet Container** manage the low-level details.

```text
Client
   │
   ▼
Servlet Container
   │
   ▼
Servlet
```

---

# Servlet Container

A **Servlet Container** (also called a **Web Container**) is responsible for running Servlets.

Popular Servlet Containers:

* Apache Tomcat
* Jetty

The Servlet Container itself runs inside the **JVM**.

```text
JVM
 └── Servlet Container
        └── Servlet
```

---

# Responsibilities of a Servlet Container

A Servlet Container automatically handles:

1. Opening network ports
2. Reading incoming bytes
3. Parsing HTTP requests
4. Managing threads
5. Creating HTTP request and response objects
6. Invoking the correct Servlet
7. Sending HTTP responses back to the client

```text
Client
   │
   ▼
Servlet Container
   ├── Open Port
   ├── Read Request
   ├── Parse HTTP
   ├── Manage Threads
   ├── Call Servlet
   └── Send Response
```

# Why Spring Framework?

Building large applications using only Servlets becomes difficult because:

* Tight coupling
* Difficult dependency management
* Large amount of boilerplate code
* Hard to scale
* Hard to test
* Hard to maintain

Spring Framework solves these problems by providing:

* Dependency Injection (IoC)
* Modular architecture
* Better code organization
* Easier testing
* Loose coupling
* Production-ready features

# Spring Boot Microservice Architecture

A typical Spring Boot microservice architecture consists of multiple independent services that communicate over HTTP/REST (or messaging systems like Kafka/RabbitMQ). Each service owns its own business logic and database.

```text
                              +----------------------+
                              |   Web / Mobile App   |
                              +----------+-----------+
                                         |
                                   HTTPS / REST
                                         |
                              +----------v-----------+
                              |     API Gateway      |
                              | (Spring Cloud Gateway)|
                              +----------+-----------+
                                         |
              ---------------------------------------------------
              |                     |                     |
              |                     |                     |
      +-------v-------+     +-------v-------+     +-------v-------+
      | User Service  |     | Order Service |     | Payment Service|
      | Spring Boot   |     | Spring Boot   |     | Spring Boot    |
      +-------+-------+     +-------+-------+     +-------+--------+
              |                     |                     |
      Spring Data JPA       Spring Data JPA      Spring Data JPA
              |                     |                     |
         Hibernate             Hibernate             Hibernate
              |                     |                     |
            JDBC                  JDBC                  JDBC
              |                     |                     |
      +-------v------+      +-------v------+      +-------v------+
      |  User DB     |      |  Order DB    |      | Payment DB   |
      +--------------+      +--------------+      +--------------+

                       Services communicate via
                  REST APIs / gRPC / Kafka / RabbitMQ
```

## Inside a Spring Boot Microservice

Every microservice follows a layered architecture.

```text
                HTTP Request
                     │
                     ▼
            Controller Layer (@RestController)
                     │
                     ▼
               Service Layer (@Service)
                     │
                     ▼
            Repository Layer (@Repository)
                     │
                     ▼
              Spring Data JPA
                     │
                     ▼
                 Hibernate
                     │
                     ▼
                    JDBC
                     │
                     ▼
                 Database
```

---

## Responsibilities of Each Layer

### 1. Controller Layer

- Receives HTTP requests
- Validates input
- Calls the Service layer
- Returns HTTP responses

---

### 2. Service Layer

- Contains business logic
- Coordinates multiple repositories or external services
- Handles transactions

---

### 3. Repository Layer

- Communicates with the database
- Uses Spring Data JPA
- No SQL required for common CRUD operations

---

### 4. Spring Data JPA

- Generates repository implementations automatically
- Simplifies database access
- Provides CRUD methods

---

### 5. Hibernate

- JPA implementation (ORM)
- Converts Java Objects ↔ Database Tables
- Generates SQL automatically

---

### 6. JDBC

- Low-level Java Database Connectivity API
- Executes SQL against the database

---

### 7. Database

Stores application data such as:

- Users
- Orders
- Payments
- Products
